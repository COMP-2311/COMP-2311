1) Project Overview (1–2 minutes)

  • Problem: Managing tasks, code changes, and team collaboration efficiently without losing visibility or control over progress.
  • End user: Development teams, project managers, and stakeholders who need to track work and maintain code quality.
  • Core functionality: Jira provides task tracking, sprint planning, and workflow management, while GitHub supports version control, branching, pull requests, and code reviews.
  • Value proposition: Together, they improve transparency, accountability, and collaboration, ensuring structured development and higher-quality releases.

2) Agile Process (3–4 minutes)

Coordination

  • How has your team coordinated work using Agile Methodology? Our team followed a lightweight Scrum approach with short sprints, daily check-ins, and clear task ownership. Work was broken into small user stories, prioritized in the backlog, and tracked continuously to keep progress visible and blockers resolved quickly.
  • Your Jira workflow? Do you use any automations? We used a simple workflow (To Do → In Progress → In Review → Done) to track task status and maintain transparency. Basic automations were used, such as automatically moving tickets when pull requests were opened/merged and auto-assigning reviewers to keep the workflow efficient.
  • Version Control practice We used GitHub with feature branches, small frequent commits, and pull requests for every change. Each PR was reviewed before merging into the main branch, ensuring code quality, collaboration, and a clear development history.

3) Lessons Learned (3–4 minutes)

Team Lessons

  • Difficulties encountered: We faced issues with unclear task scope, merge conflicts during integration, and occasional communication gaps when multiple features were developed in parallel. Also we were confused of what we needed to do and how to do them, like basic github and Jira.
  • How we handled them: We improved our communication and clarity in Jira, broke large tasks into smaller tasks, increased communication through quick check-ins, and resolved conflicts through regular merging (rebase) and code reviews, and learned how to use Jira/Github better than before.
  • Compromises/workarounds: Some lower-priority features were simplified or postponed to keep the sprint on schedule, and we focused on delivering a stable core instead of adding extra complexity.
  • Agile reflection: Agile helped us maintain visibility and adapt quickly to issues, especially through iterative development and feedback, but we learned that clear task definition and consistent communication are critical for it to work effectively and also how to interact with Jira/Github.

4) Next Steps & Adjustments (2–3 minutes)

  • How do you want to run the Web Project I based on what you have learned with this mock project?: We plan to run the project with clearer task breakdowns, and better sprint planning to avoid confusion and last-minute work. We will prioritize maintaing continuous communication, and track progress consistently through Jira to ensure steady development through github/agile.
  • How will you make sure that the project is Agile? We will maintain a clear Definition of Done, use short iterative cycles, and require reviews for all completed work to ensure quality and visibility. Regular check-ins, backlog refinement, and continuous feedback will help us adapt quickly and keep the workflow truly Agile.
  • How can you make the project Agile when the project is only 4 weeks long? We will use very short sprint cycles, keep the scope tightly focused on core features, and deliver incremental progress each week. By prioritizing the MVP (Minimum Viable Product), limiting task size, and maintaining constant feedback and iteration, we can preserve Agile principles even within a short timeline.
